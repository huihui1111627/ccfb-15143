# mvdisk — 可叠层虚拟磁盘镜像格式（Go 读写库 + 检查工具 + 检视页面）

面向"多底包叠层、按簇寻址、断电不丢数据"的虚拟磁盘镜像。库本身只依赖标准库，
底层块接口 `Block` 可接真实文件，也可接带断电模拟的内存块做测试。

## 磁盘布局

```
簇0、簇1   两个头部槽位（A/B，各自带序号与 CRC64，原子切换）
簇2 起     L1 根表 → refL1 根表 → 全部 refL2 表（创建时连续预分配）
再往后     按需分配的 L2 表簇与数据簇
```

- 所有多字节整数**大端定长**编码。
- 映射表项 8 字节：最高位 `valid`、次高位 `zero`（全零标记），低 62 位放物理字节偏移。
- 引用计数项 8 字节：高 8 位为保留位（必须为 0），低 56 位为计数。
- 打开与读写时逐项检查：偏移是否按簇对齐、是否越界、保留位是否为零、标志位组合是否合法，
  任一不合法直接返回 `ErrCorruption`。

## 两级映射与叠层

- 一级表 L1 按"组"指向 L2 表簇，一个 L2 表簇覆盖连续 E 个虚拟簇（E = 簇大小/8）；
  L2 每项指向一个数据簇。
- 未分配项沿镜像链向下找底包，一直找到最底层；整条链都没有就读**全零**。
- L2 项可把整簇标成全零（`zero` 位）：读时**不下沉底包**，写零只改标记、不写数据簇。

## 引用计数（无递归设计）

每个物理簇都有引用计数，计数本身也存放在按簇分配的两级表（refL1 → refL2）里。
为避免"给计数表分簇又要给这个簇计数"的递归，**所有 refL2 表簇在创建时一次性
预分配**，物理簇上限用不动点 `P = 2 + V + 2A + 2·ceil(P/E)` 求收敛。运行期写引用
计数只是两级查表后改一个定长项，不再动态分簇。

## 扩展区与底包路径

头部之后是一串 TLV（类型 16 位 + 长度 32 位 + 值）。底包路径是其中一种类型；
不认识的类型解析后原样保留，重写头部时整段带回。改底包路径走双槽位头部提交：
先写旧槽位并 Sync，再写新槽位并 Sync，中途断电至少有一个完整槽位可用。
底包文件当前缺失时降级为"无底包模式"打开（未映射区读零），镜像不会彻底打不开。

## 特性位与脏标记

- 不兼容特性位出现未知位 → `ErrIncompatible` 拒绝打开；兼容特性位未知 → 照常打开。
- 头部有脏标记。非正常关闭的镜像打开前自动全盘重算引用计数（`DirtyOpenReport` 可查）。

## 崩溃安全不变量

写入严格遵循"**数据先落盘并 Sync，再发布指向它的元数据**"：

1. 分配裸簇（初始计数 0）→ 写好内容并 Sync；
2. 先加引用计数，再发布 L2 指针 / L1 指针。

因此任意时刻断电，最多留下"已写好但无人引用"的**泄漏簇**，绝不会出现两个位置
指向同一簇而引用计数不对的悬挂引用。检查工具只可能报泄漏，不会报这类结构性矛盾。

## 检查与修复

- `Check`：扫描整棵映射树重算真实引用数，报告泄漏、计数偏小/偏大、结构损坏。
- `Repair`：按真实引用数改写计数、回收泄漏簇进空闲池、尾部连续空闲簇截断还空间，
  修完立即复检，复检不干净会返回错误。

## 命令行

```bash
go build -o vdisk ./cmd/vdisk
vdisk create <镜像> --size <字节> [--cluster-shift 9..20] [--base <底包路径>]
vdisk check  <镜像> [--base-dir <目录>]
vdisk repair <镜像> [--base-dir <目录>]
vdisk serve  <镜像> --addr :8080 [--base-dir <目录>]   # 检视页面
vdisk read|write|zero|set-base|stats ...
```

检视页面分四块：镜像链、两级映射表占用、每个物理簇的引用计数、检查/修复报告，
并给出读放大/写放大与文件占用。

## 压力测试（固定种子、暴力数组逐字节比对）

```bash
go run ./cmd/stress -seed 20261123 -scenarios 40
```

- 固定随机种子生成 1~4 层镜像链与上百条读写序列：随机写、写零、跨簇不对齐写、改底包路径。
- 每一步把虚拟盘整盘读出，与一个按**簇级 COW 遮蔽**维护的暴力数组逐字节比对。
- 故障注入分两种：提交点整笔丢弃、部分落盘后断电（保留高偏移数据簇、丢低偏移元数据），
  专门制造泄漏孤儿并验证悬挂引用永不出现。
- 每次写后随机冷启动重开；检查工具报出的问题只允许是泄漏，修复后复检必须干净。
- 汇总输出镜像文件大小与平均读写放大。

## 库的主要入口

`Create` / `Open`、`ReadAt` / `WriteAt` / `ZeroAt`、`Check` / `Repair`、
`Inspect`、`SetBasePath`、`Stats`，以及 `Block` 接口的文件/内存/断电模拟实现。
