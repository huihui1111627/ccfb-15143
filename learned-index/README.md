# 学习型数据库索引（Learned Index，PGM 风格）

用一个很小的分段线性模型替代整棵 B+ 树来拟合“有序键 → 数组位置”的分布函数，
支持多层递归、范围查询、不存在键查询、插入（预留空隙 + 溢出缓冲 + 单段重拟合/分裂），
并与自实现的 B+ 树、全量有序数组二分做端到端对比，附带可视化页面。

## 目录结构

```
internal/
  pla/       分段线性近似：一遍扫描贪心 + 精确有理误差保证
  learned/   多层静态索引、支持插入的动态索引
  tree/      对照用内存 B+ 树（叶链支持范围扫描）
  data/      仿真数据与查询负载（四种键分布）
  bench/     基准测试与正确性核对（有序数组二分 oracle）
  web/       可视化 HTTP 服务 + 内嵌前端
cmd/
  benchmark/ 命令行基准
  web/       可视化服务
```

## 核心算法

### 1. 分段线性近似（`internal/pla`）

对排好序的键 `x[0..n-1]`（下标即位置），用尽量少的线段
`pred(x) = slope·x + intercept` 拟合，使每点 `|pred(x_i) - i| ≤ eps`。

- **一遍扫描 O(n)**：在线维护过当前段首点的可行斜率区间 `[lo, hi]`（float64，
  每个异键点用自身误差带的两条边界斜率 O(1) 收紧），区间为空就在前一点关段、
  从当前点重开。
- **关段定参**：用水平/首末连线/在线上下界等有限候选斜率，配合一次 O(段长)
  残差扫描选使最大误差最小的截距；每个点只被线性扫描常数次，整体仍 O(n)。
  极少数浮点临界（如 eps=0 非共线）会二分最长可行前缀，不产生空洞。
- **eps=0 精确定点**：段内键唯一时用过首末点的整数直线
  `pos = floor(SlopeNum·(x-BaseKey)/SlopeDen) + BasePos`，全程整数、零浮点
  舍入；查找侧对浮点模型另留 ±1 安全余量吸收舍入。
- **重复键**：同键点在任意非竖直直线上预测值相同，按“同键 y 跨度 ≤ 2eps”
  的容量规则切分；这正是 Zipf/时间戳等强重复数据段数的天然下界。

### 2. 多层递归（`internal/learned/static.go`）

叶子层段数仍很多时，在各段起始键（天然有序）上递归再拟合一层，直到顶层
段数 ≤ 32。查找自顶向下逐层“模型预测 + 误差窗口内二分”，叶子层在数据数组的
`pred±eps` 窗口内二分。每层至多 O(log eps) 次比较，没有树的多级指针跳转。

### 3. 范围查询与不存在键

- 点查返回 `lowerBound`：命中返回首个相等位置，未命中返回插入点。重复键跨段
  时用一次二分（而非线性回扫）定位首个副本，大重复组下仍为 O(log n)。
- 范围查 `[lo,hi)` 复用两次点查分别求上下界，正确性与点查同一套误差保证。
- 预测窗口理论必中；另设防御性全量二分回退并计数（实测恒为 0）。

### 4. 插入（`internal/learned/dynamic.go`）

每个叶子段对应一个独立有序 block，预留 `gapRatio` 比例空隙：

1. 新键按段首键二分定位到段，优先用 block 空位（memmove 腾位）；
2. block 满则进该段有序溢出缓冲区；
3. 缓冲区满（`overflowCap`）或漂移超阈值时，**只重拟合这一段**——
   可能更新为一段，也可能分裂成多段；
4. 段首键组成的小有序数组作为上层路由，refit/分裂后仅重建该数组。

段范围保持不交且有序，越界键转交相邻段，只有首尾段向外扩展。

## 仿真数据（`internal/data`）

| 分布 | 仿真对象 | 特征 |
|---|---|---|
| `timestamps` | 交易时间戳（毫秒） | 按小时权重昼密夜稀、午/晚双峰、三个突发尖峰、8% 完全重复 + 同秒邻近值 |
| `uniform` | 用户编号 | 大整数域近似均匀，2% 重复 |
| `zipf` | 热门用户编号 | Zipf(s≈1.02)，少数键贡献海量重复 |
| `geo` | 地理编码 | 三个城市中心二维高斯，经纬度 Morton（Z-order）交织成一维键 |

## 运行

```bash
# 单元测试（含误差界、四分布点查/范围查正确性、动态插入、B+ 树）
go test ./...

# 基准：四分布 × 多档 eps，对比索引大小/点查/范围查/插入/搜索窗口
go run ./cmd/benchmark -n 2000000 -queries 100000 -inserts 100000 \
    -eps 8,32,128 -csv result.csv

# 可视化：http://localhost:8080
go run ./cmd/web -addr :8080 -sample 20000
```

页面展示：键密度直方图、CDF 真实点与分段直线叠加、每段最大误差（含 eps 参考线）、
一次点查的逐层预测窗口，以及分段明细表。

## 内存/时延取舍（误差上限 eps）

- eps 调小 → 段数多、索引大，但每点查的二分窗口 `≈2eps+1` 更小；
- eps 调大 → 模型极小（可达 B+ 树的数百分之一），窗口变大、单次比较略增。
- benchmark 输出的 `window_mean/window_p99` 即每次查找实际搜索的元素数，
  可直接观察这条取舍曲线。

## 实测结果（n=2,000,000，本机 Apple Silicon，10 万点查）

全部查询经有序数组二分 oracle 逐一核对，**正确性错误与回退均为 0**。

| 分布 | 索引 | 索引内存 | 点查 avg | 范围查 avg |
|---|---|---:|---:|---:|
| timestamps | B+ 树 | 25.81 MB | 556 ns | 51533 ns |
| timestamps | learned eps=32 | **0.06 MB** | **201 ns** | **563 ns** |
| uniform | B+ 树 | 26.06 MB | 606 ns | 15265 ns |
| uniform | learned eps=32 | **0.04 MB** | **198 ns** | **418 ns** |
| zipf（58% 重复） | B+ 树 | 21.77 MB | 391 ns | 2372 ns |
| zipf | learned eps=32 | **0.73 MB** | **164 ns** | **318 ns** |
| geo | B+ 树 | 26.25 MB | 300 ns | 7918 ns |
| geo | learned eps=32 | **0.93 MB** | **172 ns** | **72 ns** |

- 索引内存缩小 **30~600 倍**；点查普遍快 2~3 倍，范围查快 1~2 个数量级
  （B+ 树范围查沿叶链逐键扫描，学习型索引两次定位即得区间）。
- 插入吞吐（含 10 万次插入）：学习型动态索引 1.2万~4万 K/s，B+ 树 0.05万~1万 K/s，
  Zipf 这种强重复负载下差距最大（约 25 倍）。
- 取舍清晰：eps 从 8→32→128，索引内存持续下降，搜索窗口从约 20 增至约 260，
  见 benchmark 输出的 `window_mean/window_p99`。

## 关于“十亿级”验收

本机 16GB 内存，十亿个 int64 键仅数据就需 8GB，无法全量常驻，因此默认用
百万级（`-n` 可调，机器内存足够时可设 1e9）。算法复杂度与数据量无关，
结论可线性外推：

- 构建与查询均为 O(n) / O(log eps · 层数)，不随 n 改变单键成本；
- 索引内存只取决于**段数**，而段数由数据的 CDF 线性度决定，与 n 次线性相关
  （均匀分布下约 `n/段均长`），十亿级仍是数十 MB 量级，对比 B+ 树的数十 GB；
- 更大规模可分片（shard）后各自建索引，查询先路由到分片，与本实现的多层递归同构。

所有查询结果都用全量有序数组标准二分（`internal/bench.Oracle`）逐一核对，
基准报告中的 `correct_errors` 实测为 0。
